# Feature Chamfer 提前停止掩盖真实结果复盘（2026-07-31）

## 结论

Mixed 场景在较大 Radius 下会产生复杂、分叉且不闭合的边界。正式操作原本在中间检查处
立即停止并撤销临时结果，用户只能看到一条抽象报错，看不到实际损坏位置。这个策略阻断了
诊断，也与本工具当前的开发用途不符：即使结果拓扑有缺陷，也应优先交付最终 Mesh，让用户
直接检查真实几何。

本轮已改为：无法简化分叉输入时保留原边网继续；复杂孔洞搜索超过预算时改走已有归属信息；
最终存在开放边或非流形边时仍发布结果，并把缺陷数量写入结构化记录。

2026-08-01 的后续模型再次暴露了遗漏：逐个放开已知检查仍不能保证正式操作完成。最终修复改在
正式发布边界统一处理整类几何异常；无论异常来自 Preview、Bridge、Fill、孔洞整理、最终检查，
还是未来新增的保护检查，都必须发布中断瞬间的工作 Mesh；只有在工作 Mesh 尚未建立时才发布
当时可取得的 evaluated Mesh，并把中断阶段写入记录。

## 用户可见症状

1. Mixed、Radius 0.05 首先停止在“输入不是简单连续边线”。
2. 放开该处后，Blender 5.2 又停止在“剩余孔洞过于复杂”。
3. 继续放开后，最终检查再次因开放边和非流形边撤销结果。
4. 用户连续只能看到不同报错，始终看不到实际生成到最后的坏拓扑。

## 根因

### 根因 1：把检查结果错误地当成执行许可

输入形态、孔洞搜索预算和最终拓扑检查，本应提供诊断信息，却被实现成了强制中止条件。
这让检查逻辑决定了用户是否有权看到结果，而不是只描述结果质量。

### 根因 2：只移除第一个停止点，没有审计完整执行链

首次修复只处理了最早出现的分叉输入检查。后续仍有孔洞搜索预算和最终拓扑检查会停止、
回滚，因此“继续完成剩余步骤”的需求并未真正从正式入口贯穿到最终输出。

### 根因 3：验证使用了错误的 Blender 版本

首次验证运行在 Blender 5.1.2，而用户实际使用 Blender 5.2.0。相同场景在两个版本产生的
中间边界不同：5.1 能完成，5.2 会形成更复杂的 74 条剩余边界并触发下一层停止。用错误版本
得到的通过结果不能证明用户环境已修复。

### 根因 4：完整回归通过被误解为用户环境通过

回归入口默认找到的是另一个 Blender 安装。虽然测试全部通过，但它没有覆盖用户当前运行的
可执行程序，因此再次形成假阳性。

### 根因 5：按错误码逐项放行无法形成产品保证

内部检查点数量多且仍会演进。逐个修改已出现的错误码，只能让下一个检查成为新的停止点；
“正式操作一定交付可见结果”必须由正式入口统一保证，而不能依赖每个底层步骤都记得放行。

## 修复

- 分叉输入不再触发撤销；保留原始边网交给后续步骤。
- 孔洞搜索超过预算后，不再终止；改用已有边归属拆出可识别的闭环，其余残留保留到最终模型。
- 最终存在开放边、非流形边、零面积面或自交时，不再撤销；仍创建并发布结果。
- 最终记录明确区分干净结果与带拓扑问题的结果，并保留异常边和自交摘要。
- 新增 Mixed、Radius 0.05 的正式入口回归，要求 Blender 5.2 必须交付带真实缺陷的最终 Mesh。
- 正式入口统一接住全部结构化几何异常，优先发布中断瞬间的工作 Mesh，并继续完成清理、隐藏 source、
  选择结果和写入诊断等剩余用户流程。
- Keep Cutter 单独失败时只记录该附加结果不可用，主 Mesh 仍正常发布。
- 未知的未来几何错误码也纳入回归，避免再次退化成逐个错误码补洞。

## 回归验证

- Blender 5.2.0 下，Mixed、Radius 0.05 正式入口完成并发布最终 Mesh。
- 结果保留 74 条开放边、79 条非流形边，符合“让用户看到坏在哪里”的目标。
- Blender 5.2.0 当时的完整回归 155/155 通过；2026-08-01 增加整类异常回归后为 156/156。
- Blender 5.1.2 的历史完整回归 155/155 通过。
- 未使用图片作为自动通过证据；最终几何效果仍由用户在 Blender 中检查。

## 长期预防措施

1. 对诊断型几何工具，拓扑检查默认只记录质量，不得隐式阻止最终结果发布；真正必须中止的
   条件需要单独列出并说明为什么无法继续构造任何 Mesh。
2. 用户要求“继续执行到最后”时，必须审计从触发点到最终发布之间的全部中止和回滚路径，
   不能只移除当前最先出现的报错。
3. 涉及 Blender 行为差异时，必须先确认并使用用户当前运行版本；找到多个安装时不得以默认
   搜索顺序代替版本确认。
4. 完整回归结果必须同时记录 Blender 可执行位置与版本；二者不匹配用户环境时，只能说明
   该测试环境通过。
5. 测试应覆盖正式入口的最终可见对象，而不只断言某个底层步骤不再抛错。
6. 对带缺陷但成功发布的结果，必须保留结构化缺陷计数，使后续修复可以比较问题是否缩小。
7. 底层仍可用结构化异常停止当前不可继续的局部算法，但正式入口必须把它转换成可见结果；
   不得按错误码维护一份容易漏项的允许列表。
